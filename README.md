# 📡 אנטנות ישראל – מפת אנטנות סלולריות וכיסוי משוער

אפליקציית web (GitHub Pages) + עטיפה לאנדרואיד (APK), המציגה על גבי מפה
אינטראקטיבית את מיקומי האנטנות הסלולריות בישראל וכיסוי משוער שלהן,
לפי מפעיל ולפי דור רשת (2G/3G/4G/5G).

## תכונות
- שכבות בסיס: מפת רחובות (OSM), תמונת לוויין (Esri), מפה כהה
- Clustering חכם לביצועים גם עם אלפי אנטנות
- סינון לפי דור רשת ולפי מפעיל
- מעגלי כיסוי משוער, **מותאמים לצפיפות** - רדיוס קטן יותר באזורים עם הרבה
  אנטנות סמוכות (עירוני צפוף) וגדול יותר באזורים דלילים (כפרי/פתוח).
  עדיין heuristic בלבד, ראו הבהרה למטה
- חיפוש כתובת/רחוב/עיר (Nominatim/OpenStreetMap, מוגבל לתחומי ישראל)
- "המיקום שלי" (GPS)
- תצוגת אנטנות "בהקמה" בנפרד
- **דיווחי משתמשים על נקודות קליטה חלשה** - לחיצה על המפה במצב "דיווח",
  נשמר מקומית בדפדפן (localStorage)
- **מגמת התקנות היסטורית** - גרף sparkline + מונה "כמה אנטנות נוספו מאז
  תחילת המעקב", מבוסס על snapshot יומי שנשמר אוטומטית ב-`data/history.json`
- **כתובות שמורות + התראות** - שומרים כתובת (למשל הבית), והאפליקציה
  מתריעה (באנר + Push notification דפדפני) כשמתגלה אנטנה חדשה (בעיקר 5G)
  בקרבתה, בכל פעם שנטענת
- **מצב אופליין מלא** - Service Worker שומר את קבצי האפליקציה, הנתונים,
  ואריחי מפה שכבר נצפו, כך שהאזורים שביקרת בהם עובדים גם בלי רשת
- מותאם לנייד (bottom sheet, תפריט צד נשלף) ולדסקטופ
- PWA - ניתן "להתקין" ישירות מהדפדפן בנייד גם בלי APK
- עדכון נתונים אוטומטי יומי מ-data.gov.il דרך GitHub Actions

## מקור הנתונים
המשרד להגנת הסביבה מפרסם ב-**data.gov.il** שני מאגרים רשמיים:
- אנטנות סלולריות פעילות – https://data.gov.il/dataset/antennaactive
- אנטנות סלולריות בהקמה – https://data.gov.il/dataset/antenna_hakama

`scripts/fetch_data.py` שולף אותם דרך ה-CKAN API הרשמי וממיר ל-GeoJSON.
כרגע בתיקיית `data/` נמצאים **קבצי דוגמה** (90 נקודות מפוזרות) כדי
שהאפליקציה תעבוד out-of-the-box. יש להריץ את הסקריפט (או לחכות
להרצה האוטומטית הראשונה של ה-Action) כדי לקבל את הנתונים האמיתיים:

```bash
python3 scripts/fetch_data.py
```

> ⚠️ שמות העמודות במאגרים הממשלתיים משתנים לפעמים בין גרסאות. אם אחרי
> ההרצה תראה בסטטיסטיקה "לא ידוע" בכל השדות – פתח את
> `data/antennas-active.geojson` שנוצר, בדוק את שמות המפתחות ב-`properties`,
> ועדכן בהתאם את `FIELD_MAP` בקובץ `js/data-loader.js`.

### תדירות עדכון מומלצת
המאגר הממשלתי עצמו מתעדכן לרוב לא יותר מפעם בשבועות-חודשים (לא בזמן אמת).
לכן הגדרתי ב-`.github/workflows/update-data.yml` הרצה **אוטומטית פעם ביום**
(03:00 UTC) – זה מספיק בהחלט כדי לתפוס כל עדכון, ולא מעמיס את השרת
הממשלתי. אפשר לשנות את תדירות ה-cron בקובץ אם תרצה (למשל פעם בשבוע).

## פריסה ל-GitHub Pages
1. העלה את כל התוכן של התיקייה הזו לריפו חדש ב-GitHub.
2. ב-Settings → Pages → Source, בחר את הענף (למשל `main`) ותיקיית `/ (root)`.
3. תוך דקה-שתיים האתר יהיה זמין בכתובת
   `https://<username>.github.io/<repo-name>/`
4. ודא שב-Settings → Actions → General מופעלת ההרשאה
   "Read and write permissions" עבור ה-workflow של עדכון הנתונים
   (כדי שהוא יוכל לבצע git push לתיקיית data/).

## בניית APK לאנדרואיד
יש שתי דרכים:

### א. אוטומטית דרך GitHub Actions (הכי פשוט)
1. בטאב **Actions** ברפו, בחר בזרימת העבודה **"בניית APK לאנדרואיד"**.
2. לחץ **Run workflow** (הפעלה ידנית).
3. בסיום, קובץ ה-APK (debug) יהיה זמין להורדה תחת **Artifacts** בהרצה עצמה.
4. אפשר גם ליצור טאג גרסה (`git tag v1.0.0 && git push --tags`) כדי שהבנייה תרוץ אוטומטית.

> זהו APK **debug** (לא חתום לחנות Play). לפרסום בפועל ב-Google Play צריך
> ליצור keystore ולחתום עם `assembleRelease` – זה מעבר לסקופ הבסיסי כאן,
> ואשמח לעזור בזה כשתגיע לשלב הזה.

### ב. מקומית (על המחשב שלך)
דרוש: Node.js, Android Studio + Android SDK, JDK 17.
```bash
npm install
bash scripts/prepare-www.sh
npx cap add android      # פעם ראשונה בלבד
npx cap sync android
cd android
./gradlew assembleDebug
# הקובץ יהיה ב: android/app/build/outputs/apk/debug/app-debug.apk
```
או פשוט `npx cap open android` כדי לפתוח את הפרויקט ב-Android Studio ולבנות משם.

## התאמה אישית

## הבהרה חשובה על "כיסוי משוער"
המאגר הממשלתי כולל רק **מיקום** ו**דור רשת** של כל מוקד שידור – לא הספק
שידור, לא גובה תורן, לא כיוון אנטנה (אזימוט) ולא דגם. לכן מעגלי הכיסוי
באפליקציה הם **הערכה גסה בלבד** לפי רדיוס טיפוסי לדור הרשת, ולא תחזית RF
מדויקת. זה מוצג במפורש למשתמש גם בתוך הממשק (בפאנל הצד).

## תיקוני באג (עדכון אחרון)
אם כבר פרסת גרסה קודמת וראית "אין אנטנות בכלל" ו"אין סינון מפעילים" -
זו הייתה כנראה **הסיבה**: המאגר הלאומי ב-data.gov.il (בניגוד למראות
העירוניים שנבדקו בהתחלה) מכיל רק קואורדינטות **ITM** (רשת ישראל החדשה,
מטרים) בעמודות `X`/`Y`, ולא lon/lat ישירים. הסקריפט הישן דילג על כל
הרשומות ודרס את נתוני הדוגמה בקובץ ריק. תוקן:
- `scripts/fetch_data.py` כולל כעת המרת ITM→WGS84 מובנית (ללא תלות
  חיצונית), עם פולבאק אוטומטי כשאין lon/lat ישירים
- הגנה חדשה: אם שליפה חדשה מניבה פחות מ-30% מכמות הרשומות שהייתה בקובץ
  הקודם - הסקריפט **לא דורס** את הקובץ הקיים, ומדפיס אזהרה ברורה
- לוג של שמות השדות ברשומה לדוגמה (לאבחון מהיר אם שוב ישתנה מבנה הנתונים)
- אם בכל זאת נטענו 0 אנטנות, הממשק עצמו יציג עכשיו באנר אזהרה מפורש
- חיפוש כתובות: מנסה קודם עם הגבלה לישראל (`countrycodes=il`), ואם אין
  תוצאות מנסה שוב בלי ההגבלה - כי ישובים מעבר לקו הירוק (גבעת זאב,
  מעלה אדומים וכו') לפעמים לא מתויגים "il" ב-OpenStreetMap. גם הכתובות
  המוצגות עברו ניקוי (רחוב+יישוב במקום המחרוזת ההיררכית המלאה)

**מה לעשות עכשיו:** הריצו שוב את ה-Action "עדכון נתוני אנטנות" (טאב
Actions → Run workflow), או `python3 scripts/fetch_data.py` מקומית,
ובדקו בלוג כמה רשומות תקינות נוצרו ואם היה שימוש בפולבאק ITM.

## תיקוני עדכון נוסף (חשוב לקרוא!)
לאחר בדיקה בפועל התגלו 3 בעיות:

1. **"מעט מדי אנטנות" למפעיל מסוים** - אם אתה עדיין רואה מספרים נמוכים
   מאוד (עשרות בודדות בכל הארץ) - כנראה שה-Action לשליפת נתונים אמיתיים
   עדיין לא רץ בהצלחה, ואתה רואה את **נתוני הדוגמה** (מסומנים כ-SAMPLE
   ב-`data/meta.json`). בדוק בטאב Actions את הלוג של ההרצה האחרונה.

2. **Service Worker היה תוקע גרסה ישנה של הקבצים** - התיקון הראשוני
   שנשלח לא נכנס לתוקף אצל חלק מהמשתמשים כי `sw.js` שמר קבצי JS/CSS
   ב-cache-first (=לתמיד, עד לניקוי ידני). תוקן: קבצי קוד (html/js/css)
   נטענים כעת ב-network-first (מתעדכנים אוטומטית כשיש רשת), ורק אריחי
   מפה/אייקונים נשארים cache-first. **גרסת הקאש עודכנה מ-v1 ל-v2** כדי
   שהדפדפן יזרוק את הישן. אם עדיין רואים התנהגות ישנה - נקו את נתוני
   האתר בדפדפן (Site data / Storage) פעם אחת ידנית.

3. **"כיסוי לא ברור, רק עיגול מקווקו"** - נוסף כפתור **"חשב כיסוי מדויק
   יותר"** בתוך הפופ-אפ של כל אנטנה (על פי דרישה, לא אוטומטי לכולן).
   הוא מחשב "ענן" לא-סימטרי מבוסס **קו-ראייה אמיתי מול נתוני תבליט
   (SRTM, ~30מ' רזולוציה)** - הרים/גבעות בדרך חוסמים ומקצרים את הכיסוי
   בכיוון הזה. **מגבלה חשובה:** המאגר הממשלתי לא כולל הספק שידור, גובה
   תורן אמיתי או אזימוט אנטנה - כך שזו עדיין הערכה, לא מדידת שדה
   אלקטרומגנטי. תכסית (יער/מבנים) עדיין לא נכללת - ראו "רעיונות להרחבה".

4. **"המפה כאילו מפרידה חלקים מהמדינה"** - זה לא בחירה של הקוד שלי,
   אלה אריחי OpenStreetMap הסטנדרטיים (Mapnik) שמציגים גבולות מנהליים
   כפי שהם מתויגים ב-OSM. הוחלף ל-**CartoDB Voyager** כברירת מחדל -
   סגנון נקי יותר עם פחות הדגשת גבולות אזוריים.

## עדכון גדול: שדות אמיתיים + תבליט + תכסית + הספק אמיתי
בעקבות בדיקת לוג הרצה אמיתית (8,475 אנטנות פעילות + 326 בהקמה נשלפו
בהצלחה!) התגלו שמות השדות האמיתיים ב-data.gov.il, ששונים ממה שהונח
מלכתחילה:

| שדה באפליקציה | שם עמודה אמיתי במקור |
|---|---|
| מפעיל | `חברה` |
| דור רשת | `טכנולוגיית שידור` |
| עיר | `עיר` / `ישוב` |
| הספק שידור תיאורטי מרבי | `עוצמה מרבית תיאורטית בµW לסמ"ר` |
| % מסף בריאות (מדידה בפועל) | `תוצאה מירבית ב% ביחס לסף הבריאות` |
| סוג אתר | `סוג אתר` |

`js/data-loader.js` עודכן עם המיפוי הנכון + זיהוי גמיש יותר לדור רשת
(GSM/UMTS/LTE/NR ולא רק "2G"/"3G" מילולי).

### נתוני הספק אמיתיים (חדש!)
המאגר כן כולל הספק שידור תיאורטי מרבי חלקי (מתוך היתר הקרינה)! זה
שימש לשיפור מהותי בחישוב הרדיוס: `powerAdjustedRadius()` ב-`js/app.js`
משווה את ההספק של כל אנטנה לחציון ההספק של אנטנות אחרות **מאותו דור
רשת** בכל הארץ, ומתאים את הרדיוס לפי `sqrt(הספק/חציון)` (פיזיקלית
נכון: אובדן מרחב חופשי → הספק מתקבל ∝ 1/מרחק²). זה עדיין הערכה (חסר
גובה/אזימוט/דגם אנטנה מדויקים), אבל מבוססת נתון רישוי אמיתי ולא ניחוש
גורף. מוצג גם בפופ-אפ של כל אנטנה.

### תכסית (landuse) - חדש!
`js/terrain-coverage.js` שולף עכשיו גם פוליגוני תכסית אמיתיים
(יער/מים/בינוי) מ-**OpenStreetMap דרך Overpass API** (חינמי, ללא
מפתח) סביב האנטנה הנבדקת, ומכווץ/מרחיב את כל כיוון בענן הכיסוי לפי
קטגוריית הקרקע שם (יער מנחית יותר, מים כמעט ולא, עירוני צפוף מנחית
בינוני). זה רץ **במקביל** לבדיקת קו-הראייה מול התבליט (SRTM), אז כל
כפתור "חשב כיסוי מדויק" נותן תוצאה שמשלבת: תבליט + תכסית + הספק אמיתי.

**למה לא נבנה מראש (batch) לכל הארץ:** גם opentopodata וגם Overpass
הם API-ים חיצוניים חינמיים עם הגבלת קצב הוגנת (fair use) - הרצה על
8,475 אנטנות בבת אחת תחרוג ממנה במהירות ועלולה לגרום לחסימה זמנית של
כתובת ה-IP של GitHub Pages/הדפדפן. לכן זה נשאר **on-demand, אנטנה
אחת בכל פעם**, לפי לחיצת המשתמש.

## חדש: חישוב מקדים לילי לכיסוי (תבליט+תכסית לכל האנטנות)
כדי שכפתור "כיסוי מדויק" לא יצטרך לחכות ל-API בכל לחיצה, נוסף תהליך
**offset-based שרץ כל לילה ברקע** ומחשב בהדרגה תבליט+תכסית לכל 8,475
האנטנות:

- `scripts/precompute_coverage.py` - מעבד אנטנות אחת-אחת (תבליט מ-
  opentopodata + תכסית מ-Overpass, במקביל לכל אנטנה), שומר קובץ קטן
  נפרד לכל אנטנה תחת `data/coverage/<key>.json`, ושומר "איפה עצר"
  ב-`data/coverage-precompute-state.json`
- `.github/workflows/precompute-coverage.yml` - רץ **כל לילה ב-01:00
  UTC** (וגם ניתן להפעלה ידנית מטאב Actions), בתקציב זמן של כ-5 שעות
  (מתחת למגבלת 6 השעות של GitHub Actions), וממשיך בדיוק מה-offset
  שנשמר בפעם הקודמת - כך שתוך כמה לילות (בערך 2-4, תלוי בעומס על
  ה-API-ים החיצוניים) כל 8,475 האנטנות יהיו מחושבות, ואז זה חוזר
  להתחלה כדי לרענן
- `js/terrain-coverage.js` בודק קודם אם קיים קובץ מוכן מראש לאנטנה
  שנלחצה (טעינה מיידית, בלי שום קריאת API) - ורק אם עוד לא הגיע
  תורה, נופל לחישוב חי כבעבר (איטי יותר, תלוי ב-API בזמן אמת)
- הסיידבר בממשק מציג **אחוז התקדמות** של המעבר הלילי הנוכחי

**חשוב:** ה-workflow הזה **לא** רץ אוטומטית מרגע ההעלאה - הוא מתוזמן
ל-01:00 UTC, אז אחרי שתעלה את הקבצים, אפשר גם להריץ אותו ידנית פעם
אחת (Actions → "חישוב מקדים לכיסוי (תבליט+תכסית)" → Run workflow) כדי
לא לחכות ללילה. אפשר גם לקבוע כמה שעות ריצה בטופס ההרצה הידנית.

**גודל הריפו:** קובץ נפרד לכל אנטנה (~1-1.5KB) × 8,475 = בערך 10-13MB
נוספים לריפו לאחר מעבר מלא - סביר לגמרי לריפו GitHub רגיל.

**מגבלת דיוק חשובה:** טווח הסריקה בחישוב המקדים קבוע על 6 ק"מ (במקום
מותאם דינמית לכל אנטנה כמו בחישוב החי). במקרי קיצון נדירים (אנטנת 2G
כפרית עם גם צפיפות נמוכה מאוד וגם הספק גבוה מאוד) ייתכן שהרדיוס
התיאורטי חורג מ-6 ק"מ ואז החישוב המוכן-מראש "יחתוך" אותו שם - זה
compromise סביר בין דיוק לזמן ריצה, מתועד כאן לשקיפות.

## הערות על הפיצ'רים החדשים
- **דיווחי קליטה חלשה וכתובות שמורות נשמרים רק במכשיר** (localStorage) -
  אין כרגע שרת/בסיס נתונים משותף, כך ששני משתמשים שונים לא רואים דיווחים
  אחד של השני. אם תרצה שיתוף בין משתמשים בעתיד - הדרך הכי מהירה היא
  לחבר Firebase Firestore (חינמי בהיקפים קטנים) ולהחליף את `js/reports.js`
  לקרוא/לכתוב משם במקום מ-localStorage.
- **התראות** נבדקות רק כשהאפליקציה *נטענת מחדש* (אין Push אמיתי מהשרת,
  כי מדובר באתר סטטי ב-GitHub Pages ללא backend). זה עדיין שימושי
  למשתמש שפותח את האפליקציה מדי כמה ימים.
- **גרף המגמה ההיסטורית** יתמלא בנתונים אמיתיים ככל שה-GitHub Action
  היומי ירוץ; כרגע יש 14 ימי דמו לצורך הדגמה בלבד.
- **רדיוס כיסוי לפי צפיפות** מבוסס על ספירת אנטנות סמוכות בלבד (proxy
  לצפיפות עירונית) ולא על נתוני אוכלוסין רשמיים - שיפור עתידי אפשרי הוא
  חיבור ל-CBS (הלשכה המרכזית לסטטיסטיקה) לצפיפות אוכלוסין אמיתית לפי יישוב.

## רעיונות נוספים להרחבה עתידית
- שכבת חום (heatmap) לצפיפות אנטנות כללית
- ייצוא לדוח PDF/Excel של אנטנות באזור נבחר
- השוואת כיסוי בין שני מפעילים זה לצד זה (split view)
- תמיכה ב-iOS (Capacitor תומך גם ב-iOS עם אותו קוד, נדרש Mac + Xcode)
- שילוב נתוני תכסית (ESA WorldCover / CORINE) בחישוב "הכיסוי המדויק" -
  יער/מבנים גבוהים יגרמו לניחוי נוסף, לא רק חסימת קו-ראייה מלאה
- חישוב מקדים (batch, לא on-demand) של "עננים" מבוססי תבליט לכל
  האנטנות דרך GitHub Action, כדי שהתצוגה תהיה מיידית ולא תלוית API
  חיצוני בזמן אמת - ידרוש ניהול קצב קפדני מול opentopodata (או מעבר
  למקור SRTM מקומי בתוך ה-Action עצמו, ללא תלות ב-API חיצוני בכלל)
